# Native Android Notification Monitor

## 1. Objective

Build a native Android application in Kotlin that:

1. Runs as a background Android service.
2. Reads notifications generated by other Android applications using `NotificationListenerService`.
3. Stores received notification events locally.
4. Displays notification history in the app.
5. Allows filtering notifications by source application.
6. Can generate local notifications.
7. Continues receiving notification events when the app UI is closed.
8. Does not require Android Studio for development or building.
9. Builds entirely through AWS CodeBuild.
10. Produces an installable APK and optionally an Android App Bundle (AAB).

The application must be a **native Android application**.

Do NOT use:

* Expo
* React Native
* Flutter
* Capacitor
* Cordova
* WebView-based UI

Use Kotlin + Android SDK + Gradle.

# 5. Main Feature: NotificationListenerService

Implement:

```kotlin
class NotificationListener : NotificationListenerService()
```

Register it in `AndroidManifest.xml` with:

```xml
<service
    android:name=".notification.NotificationListener"
    android:label="@string/app_name"
    android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE"
    android:exported="true">
    
    <intent-filter>
        <action android:name="android.service.notification.NotificationListenerService" />
    </intent-filter>
</service>
```

The service must receive:

```kotlin
override fun onNotificationPosted(sbn: StatusBarNotification)
```

and:

```kotlin
override fun onNotificationRemoved(sbn: StatusBarNotification)
```

Initially, notification removal events do not need to be persisted, but structure the code so this can be added later.

# 6. Notification Data Model

Persist notification events using Room.

Create:

```kotlin
@Entity(tableName = "notifications")
data class NotificationEntity(
    @PrimaryKey(autoGenerate = true)
    val id: Long = 0,

    val packageName: String,

    val appName: String?,

    val title: String?,

    val text: String?,

    val subText: String?,

    val bigText: String?,

    val category: String?,

    val notificationKey: String?,

    val postedAt: Long,

    val receivedAt: Long,

    val isOngoing: Boolean,

    val isClearable: Boolean
)
```

Do not store notification icons or large binary payloads initially.

Do not store raw notification objects.

# 7. Notification Parsing

Create a dedicated:

```kotlin
NotificationParser
```

Responsibilities:

* Convert `StatusBarNotification` into `NotificationEntity`.
* Safely extract notification fields.
* Handle missing fields.
* Never crash because a notification has unexpected/missing extras.
* Handle different notification styles.

Extract, where available:

```text
packageName
application name
title
text
subText
bigText
category
notification key
posted timestamp
ongoing status
clearable status
```

Use safe access to:

```kotlin
notification.extras
```

including:

```text
Notification.EXTRA_TITLE
Notification.EXTRA_TEXT
Notification.EXTRA_SUB_TEXT
Notification.EXTRA_BIG_TEXT
```

Do not assume every notification contains all of these.

# 8. Duplicate Handling

Some applications may update an existing notification rather than creating a new one.

The system must avoid treating every update as a completely unrelated event where possible.

Use the Android notification key:

```kotlin
StatusBarNotification.key
```

Store it as:

```text
notificationKey
```

The initial implementation should record posted events, but the repository should be structured so notification updates can later be detected.

Do not build complicated deduplication logic unless necessary.

# 11. Notification Listener Lifecycle

The listener must operate independently from `MainActivity`.

The app UI may be completely closed while the listener remains registered with Android.

Do not implement a polling loop.

Do not attempt:

```kotlin
while (true) {
    ...
}
```

to monitor notifications.

Android's `NotificationListenerService` is the source of notification events.

When:

```kotlin
onNotificationPosted()
```

fires:

1. Parse notification.
2. Check whether the source application is allowed.
3. Persist notification asynchronously.
4. Optionally trigger configured processing.
5. Do not perform long-running work directly on the service callback thread.

Use Kotlin coroutines appropriately.

# 12. Source Application Filtering

Users must be able to enable/disable monitoring for individual applications.

Create an application settings model:

```text

enabled
```

The app should discover installed applications capable of producing notifications.

Display:

```text

Monitoring enabled/disabled
```

Example:

```text
WhatsApp             ON
Telegram             ON
Slack                OFF
Gmail                ON
Instagram             OFF
```

Store these settings locally.

Default behavior:

* Monitoring enabled for all detected apps.
* Allow the user to disable individual apps.

If a notification comes from a disabled app, do not persist it.

The core background architecture is:

```text

      │
      │ notification posted
      ▼
NotificationListenerService
      │
      ▼
NotificationParser
      │
      ▼
```

The UI is not involved.

Closing the Activity must not stop notification monitoring.

Do not create a foreground service for the notification listener unless a later requirement specifically requires one.

Do not rely on a React/JavaScript runtime.

# 24. Error Handling

Notification processing must be highly fault tolerant.

A malformed notification from another application must never crash the service.

Use:

```kotlin
try/catch
```

around notification parsing and persistence where appropriate.

Log errors using:

```kotlin
Log.e(...)
```

during development.

Do not log notification contents by default.

Avoid logging potentially sensitive notification text.

---

# 25. Privacy

Notification contents can contain sensitive personal information.

Therefore:

* Do not send notification content to a server.
* Do not upload notification contents to AWS.
* Do not include notification contents in analytics.
* Do not log notification contents.
* Keep notification data on-device.
* Clearly explain notification access in the app.
* Provide "Clear all history".

The initial application should be completely local.

# 35. Implementation Principles

Follow these principles:

1. Native Android only.
2. Kotlin only.
3. Clean separation between Android service, repository, database and UI.
4. Notification monitoring must work independently of the UI.
5. Never poll for notifications.
6. Never use an always-running Activity.
7. Never store notification data remotely.
8. Do not log notification contents.
9. Handle malformed third-party notifications safely.
10. Keep dependencies minimal.
11. Prefer AndroidX/platform APIs.
12. The project must build without Android Studio.
13. The project must build in AWS CodeBuild from a clean environment.
14. Keep all configuration reproducible.
15. Do not over-engineer the initial implementation.
